# 迷宫架构与编辑器实现说明

更新日期：2026-10-19。对应首版折叠迷宫代码改造。

## 1. 自动生成与圆角方案

地图采用**编辑器自动生成、校验后发布**，不是每次进关随机生成。已提供 12 张按固定种子生成的地图；可以在编辑器重新生成、手工调整后保存。玩家进入关卡时缓存实际地图、种子、生成器版本和内容版本，重开、续玩、更新算法都不会让正在玩的地图悄悄改变。

生成器使用固定的 xorshift32 算法，不依赖不同运行环境的随机实现。对候选地图执行“坐标＋折叠状态”寻路，并单独计算最少必要切换次数；前四关分别要求 0、1、2、3 次切换。找不到符合条件的地图会报错，不能把未经验证的地图当作成功结果发布。发布前仍应人工试玩调整路线辨识度；可解不等于有趣。

圆角采用**程序化 UGUI 合并网格**：道路由圆形节点、连接条和内转角弧面组成，外转角、道路末端及内转角均由几何顶点绘制。视图颜色可以改，不需要 AI 出图或为每种转角准备图片。

| 方案 | 取舍 |
| --- | --- |
| 每格一个 Image / GameObject | 实现简单，但增加对象、布局和 Canvas 管理开销，本次不采用 |
| 每关生成 Texture2D | 可以做到整图绘制，但生成上传、纹理内存和折叠分区管理更复杂，本次不采用 |
| 每格 Tilemap / Sprite | 可用于后续世界场景，但当前竖屏 UI 玩法没有必要引入额外地图系统 |
| 三部分合并 UI 网格 | 当前采用；同材质、无每格对象、无碰撞体，分区位移即可折叠 |

每次切换关卡或地图配置变化时重建网格；拖动只更新球的位置，折叠只改变分区 Transform。静态地图使用独立子 Canvas，HUD 和箭头按状态版本刷新。实际 Draw Call、帧时、GC 和抗锯齿效果仍以 Unity Profiler 与目标手机实测为准，不能将理论优势当作实测性能结论。

圆角仅为视觉表现，碰撞仍以格子道路中心线和合法连接判定，避免装饰性圆角改变谜题答案。当前道路宽度为格子宽度的 72%，内转角半径为 12%；可在 `MazeBoardGraphic` 中调整。最初版本没有增加专用图片或 Shader。

## 2. 目录与职责

```text
Assets/GameScripts/HotFix/GameLogic/Maze/
  Domain/
    MazeData.cs              地图 DTO、只读运行时地图、玩法生命周期接口
    MazeProgressData.cs      存档 DTO、存储接口
    FoldMazeRules.cs         连接、折叠合法性、提示搜索、必要切换计算
    FoldMazeGameplay.cs      连续移动、吸附、出口、提示片段、稳定状态
  Generation/
    FoldMazeGenerator.cs     确定性生成、清理不可达装饰、校验
  Application/
    MazeSession.cs           折叠关卡编排、提示消费、解锁、奖励归属
    MazeProgress.cs          双槽校验存储，与旧游戏隔离
    MazeRewardedVideo.cs     SDK 广告适配、超时、完成结果
  Presentation/
    MazePresenter.cs        依赖组装、输入转发、资源与生命周期
    MazeScreen.cs           页面、选关、结算、折叠与吸附动画
    MazePointerInput.cs     手指位移转换，不判定道路或出口
    MazeBoardGraphic.cs     分区圆角道路网格、球与出口图形

Assets/Editor/Maze/
  MazeLevelEditorWindow.cs  生成、编辑、验证、发布、内存试玩

Assets/AssetRaw/Configs/
  MazeCampaign.json        已校验的首批 12 关
  MazeAds.json             新游戏自己的广告位配置，默认留空

TEngine/Tests/Maze.Tests/   无 Unity 依赖的规则和流程测试
```

依赖方向为 Presentation → Application → Domain；Generation 只依赖 Domain。Domain 不引用 Unity、不读取 Transform、不调用 SDK、不访问存储。地图运行时对象复制配置数组，视图只能查询道路，不能修改格子。

`GameApp.StartGameLogic` 已切换为迷宫启动，异步加载关卡目录、广告配置和现有字体。经确认，旧启动函数、笔画玩法、旧关卡编辑器及配套资源已删除，不再保留停用的业务入口。通用 UI 框架、单例管理、SDK、热更加载和当前使用的字体保留。

新增代码仍属于现有 `GameLogic` 热更程序集，没有另建必须追加到 HybridCLR 热更列表的新程序集。编辑器代码在 `Assets/Editor` 下，不进入玩家包。JSON 放在已有 YooAsset 的 Configs 采集路径中，地址分别为 `MazeCampaign`、`MazeAds`；发布包时需照常重新构建资源与热更 DLL。

## 3. 连续移动与数据提交

手势锁定横轴或纵轴，将触点位移转换为可见格子长度。规则层逐条消耗连接边，防止高速拖动穿墙；沿轴反向拖动也会检查当前边的剩余距离。折叠接缝跨越的是一条可见边，不改变原始格子 ID。

运行时保存两种数据：

- 临时状态：当前移动边、边上的比例、拖动状态、提示显示。仅在内存中。
- 稳定状态：原始格子 ID、是否折叠、提示使用、通关与跳过。用于持久化。

松手后选择最近的合法格子；等距选择最近经过的中心。吸附动画结束才提交位置。折叠动画也在结束后提交规则状态。切后台会取消未完成动作，恢复动作前稳定状态。

出口判定优先：小球中心进入出口格范围就立即完成，即使仍在拖动、单帧跨过整个出口或者尚未经过格子中心，也会被连续路径检测捕获。通关先提交数据，再播放结算动画。

## 4. 关键缓存点与恢复

| 时机 | 保存内容 |
| --- | --- |
| 首次进关 | 实际地图快照、种子、内容版本、起点、初始折叠状态 |
| 吸附完成 | 最终格子和地图状态 |
| 折叠／展开完成 | 新地图状态，原始格子身份不变 |
| 成功请求免费提示 | 免费提示已使用，不缓存可见箭头 |
| 广告请求建立 | 请求 ID、用途、所属关卡 |
| 广告确认完成 | 请求消费与待兑现奖励放入同一快照 |
| 经过出口 | 通关、出口位置、解锁范围，一次提交 |
| 跳过 | 跳过标记、解锁范围，不写通关标记 |
| 重开、选关、切后台、退出 | 保存稳定进度，免费提示使用记录保留 |

存储键为 `PaperFold.Maze.v1.0` / `PaperFold.Maze.v1.1`，与旧 `gameCache` 隔离。每次写下一槽，附加递增序号与校验值；读取最新的有效槽，一槽损坏可回退另一槽。校验值用于发现数据损坏，不用于防作弊。

桌面使用 PlayerPrefs，当前微信 WebGL 分支复用项目的 WX 存储接口。同步落盘只发生在关键节点，不发生在每帧拖动中；后续如果地图数量或快照体积显著增大，应将存储接口替换为分关异步存储。其他 WebGL 平台需要另接存储适配器，不能直接沿用微信分支。

内容版本变化或旧地图非法时，恢复配置中的起点，保留提示消费和历史完成标记。未确认完成的广告不补奖；已确认但未展示的提示保留在所属关卡。迟到回调不能跳过当前其他关卡，重复请求 ID 不重复发奖。存储失败会显示错误并保留内存进度，后续关键节点再次尝试写入。

## 5. 后续两种玩法如何接入

共用 `IMazeGameplay` 生命周期、地图查询、存储接口、合并道路视图和输入适配层，**不把三种玩法塞进一个大类的 switch**。

| 玩法 | 独立规则与状态 | 需要特别处理 |
| --- | --- | --- |
| 折叠迷宫 | `FoldMazeRules`、`FoldMazeGameplay` | 原始格子＋折叠状态，接缝连通 |
| 推箱子迷宫（后续） | 新建 `SokobanRules`、`SokobanGameplay` | 玩家、箱子集合、目标集合；推动原子提交；死锁检测与撤销 |
| 双球迷宫（后续） | 新建 `DualBallRules`、`DualBallGameplay` | 两球状态；同一输入同步判定；目标、阻挡及两球碰撞规则 |

`MazeSession` 和 `MazePresenter` 目前是折叠模式的应用编排，不假装已经支持箱子或双球。新模式增加自己的编排／Presenter，通过共同生命周期管理加载与释放；不要将箱子字段硬塞进 `FoldMazeGameplay`，也不要直接复用折叠模式的 BFS 状态。提示求解必须针对各玩法的完整状态实现。

`MazeMode` 已为后两种玩法预留标识，当前加载非 Fold 关卡会明确拒绝，避免未经实现的玩法被错误执行。双球是否共享控制、箱子能否连续推动等产品规则仍需各自策划确定。

## 6. 编辑器使用

1. 打开 `Tools → PaperFold → 迷宫关卡编辑器`。
2. 选择关卡，设置种子与最少切换次数，生成候选地图。
3. 使用“道路 / 墙”“设置起点”“设置出口”工具调整；折叠预览使用相同原始格子索引。
4. 修改已发布地图时递增内容版本。
5. 点击“校验当前关”查看最短逻辑操作数和最少必要切换次数。
6. 点击“校验全部”，前四关会额外检查教学标记、展开开局和必要切换数。
7. “保存目录”只有校验通过才写入 JSON。
8. Play 模式中可点击“试玩当前关”，使用内存存档，不消费真实玩家进度。停止 Play 模式结束试玩。

编辑器的格子图强调配置可读性，游戏内则使用圆角合并网格，不为编辑器每个按钮生成正式运行时对象。

## 7. 验证与当前边界

核心测试命令：`dotnet run --project TEngine/Tests/Maze.Tests`。无外部测试包依赖。

已覆盖：连续拖动与反向、多格吸附、切后台取消临时动作、折叠禁区、接缝双向连接、展开归属、出口经过判定、穿墙拦截、提示去重／重开消费、12 张地图可解性与固定种子复现、提示路径逐边合法、跨会话提示记录、跳过与通关区分、广告失败／重复／迟到、待兑现提示恢复、非法坐标恢复、存储错误通知。

已使用本机 Unity 2022.3 参考程序集，对全部 GameLogic 源码及新增编辑器源码执行 C# 编译检查。项目正在另一 Unity 实例中打开，独立 batchmode 检查被项目锁阻止，因此尚未完成实际 Play 模式视觉验收、真机性能采样或真实广告联调。

新游戏广告 ID 默认留空，点击观看会走失败保留进度流程；请在 `MazeAds.json` 配置本项目自己的广告位。旧 SDK 的 Editor 模式会模拟完整观看，填入测试配置后的编辑器成功结果不能当作真实平台验收。

当前交付是可继续开发的折叠玩法架构与首批内容：教学已有按关卡显示的短句，尚未制作手势动画和逐状态教学遮罩；最终美术、音效、机型适配与关卡趣味性需要在 Play 模式和设备上继续验收。

## 8. 旧项目清理结果

本次确认删除 331 个文件：88 个 C#、16 个预制体、13 个旧关卡资产、14 个动画、2 个旧场景及 198 个元数据文件。删除范围包括旧 Game／CorePlay、旧业务 UI、旧存档／道具／广告业务封装、旧业务本地化、笔画关卡编辑器、旧字体生成回调及其绑定的旧玩法资源。

`Assets/Scenes/main.unity` 是构建入口，保留；被删除的 `SampleScene`、`LevelEditScene` 为旧游戏示例／编辑场景。删除前检查引用闭包，删除后扫描所有保留的 prefab、asset、unity、mat、controller、anim，对本次删除 GUID 的剩余引用为 0。C# 编译检查及 4,551 项测试断言通过。

按当前 `MazeBoardGraphic` 生成公式及 12 张地图静态核算：每关道路网格为 540～1,260 顶点、396～908 三角形，不含字体、球、出口和 HUD。这是几何预算，不是 GPU 帧时或 Draw Call 实测。清单与核算结果分别记录于 `TEngine/Tests/legacy-cleanup-manifest.json` 和 `TEngine/Tests/maze-geometry-budget.json`。

共享框架、第三方库及 Luban 生成工具链没有因为暂时未调用而一并删除；它们属于项目基础设施，不等同于已淘汰的旧游戏业务。发布前仍需重新构建 YooAsset 资源和热更 DLL，历史已构建包不会随源码删除自动更新。
