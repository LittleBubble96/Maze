# 折叠迷宫小游戏策划案

版本：V1.3｜更新日期：2026-10-19｜项目：Maze

本文保留已确定的核心玩法，并补充首版实现规则。标注“建议”的数量、尺寸和时长是初始调优值，需通过试玩确认；其余补充规则作为首版设计口径。本文是策划规格，不代表功能已经开发完成。

## 一、产品定位与版本范围

一款以空间关系变化为核心的轻量网格解谜游戏。玩家控制小球沿道路移动，通过折叠与展开固定区域，让原本断开的道路接通，最终到达出口。

核心体验：观察断路 → 尝试移动 → 改变地图连接 → 跨越接缝 → 必要时重新展开 → 到达出口。解谜重点是理解两种地图状态，而非操作速度。

- 首版建议采用竖屏、单指操作；美术以纸张、折痕和清晰的格子道路为主。
- 每关只有一个起点、一个出口、一处固定纵向折叠区域和一个小球。
- 首版仅包含道路、墙壁、起点、出口，不加入钥匙、传送门、移动机关、敌人或随机地形。
- 折叠、展开和重新开始免费，不限次数；无倒计时、体力、步数限制和失败惩罚。
- 唯一道具为分段提示。商业化入口仅为玩家自愿观看的激励视频：额外提示、跳过本关。
- 不设置强制插屏，不以广告限制正常通关后的下一关。
- 首版采用本地进度；云存档、多设备同步、排行榜和付费购买不纳入本次范围。

## 二、核心玩法与判定

### 2.1 地图与坐标

地图为矩形网格，以原始展开地图的行、列作为格子的永久标识。左上角为 `(0, 0)`，行向下增加，列向右增加。

固定折叠区由连续的完整列组成，贯穿地图高度，不能覆盖最左或最右列；左右两侧都必须保留至少一列。首版起点和出口都放在折叠区外，避免目标隐藏造成理解负担。

格子基础类型只有道路与墙。起点、出口是道路上的标记。小球移动过程中可处于相邻道路格中心之间，移动结束后吸附到道路格中心；无斜向通行、无越界、无穿墙跳格。

### 2.2 移动操作

- 在任意非 UI 操作区域向上、下、左、右滑动，小球随滑动连续移动；一次长滑动可以经过多格，不再限制为一格。
- 建议按手指沿有效方向的位移等比例驱动小球，初始比例为 1:1；手指停止滑动时小球也停止跟随，不自动滑向道路尽头，不增加松手惯性。
- 每段位移按较大的轴判定方向，不锁死整次手势。一次按住可上下左右转向；换轴时衔接当前边上最近的可通行格中心，转向被墙阻挡时保持原位，不斜穿墙。
- 起手有效位移阈值为迷宫格子边长的 12%，持续拖动阈值为 2.5%，仅用于识别手势，不代表移动步长；按实际设备触控体验调整。
- 手指从按钮或弹窗开始的手势不触发移动；地图外空白区域可以起手；仅接受第一根触点。
- 墙壁或边界阻挡时，小球最多移动到阻挡前最后一个道路格的中心，给出轻微碰撞反馈；超出部分的拖动位移丢弃，反向拖动立即响应。快速滑动也需逐段检测道路，不能只检查最终落点而穿过墙壁。
- 松手后，根据小球当前位置吸附到最近的合法道路格中心。候选必须位于当前移动轴上，且到该中心的路径连续可通行，不能隔墙吸附到其他道路；距离相同时选择本次移动中最近经过的格子中心。
- 建议吸附动画为 0.12 秒。拖动期间持续响应当前手势；吸附期间不接收新手势、不缓存输入。未达到手势阈值则保持原格子。
- 拖动和吸附期间不能折叠、请求提示、重开或跳过；吸附完成后恢复这些操作。小球的稳定格子归属以最终吸附结果为准。
- 开发调试可支持方向键或 WASD：按住连续移动，释放后吸附，与触屏共用碰撞和吸附规则。

### 2.3 展开与折叠

1. 展开时，所有列可见，小球可进入折叠区内的道路。
2. 折叠时，中间折叠区隐藏，左右两部分平移靠拢。两侧不旋转、不镜像，格子内容保持不变。
3. 靠拢后，同一行、接缝两侧紧邻的格子均为道路时，允许横向互通；任一侧为墙则不可通过。
4. 展开时，接缝快捷连接消失，恢复原始四邻接关系。不存在隔着中间区域跨越移动。
5. 切换不改变小球所属的原始格子。小球随所在部分移动，不能根据动画后的屏幕位置重新归属格子。
6. 小球处于折叠区时，点击“折叠”不执行切换，显示“请先走出折叠区域”。该按钮保留点击反馈。
7. 折叠与展开不限次数，不消耗提示或其他资源。
8. 切换动画期间暂停移动，屏蔽折叠、提示、重开和跳过等操作。动画完成后更新状态和按钮，再恢复输入。
9. 建议切换动画为 0.35 秒；以明显折痕表现区域收起，以短暂接缝亮线表现道路接通。

按钮文字表示将要执行的动作：当前展开时显示“折叠”，当前折叠时显示“展开”。界面另以小标签显示“已展开／已折叠”，避免将动作与状态混淆。

### 2.4 接缝示例

下例仅说明连接规则，不是一张完整关卡图；`·` 表示道路，`#` 表示墙。

```text
展开：左侧边缘 | 中间折叠区 | 右侧边缘
第 1 行： ·  |    # #     |  ·
第 2 行： ·  |    · #     |  #

折叠：左侧边缘 | 右侧边缘
第 1 行： ·  ↔  ·    两侧都是道路，可以跨接缝
第 2 行： ·  |  #    右侧为墙，不能跨接缝
```

### 2.5 通关与重新开始

小球的合法移动路径只要进入出口所在格子，即立即判定通关，不要求经过出口格中心、松手或最终停留在出口。判定以小球中心进入出口格范围为准；仅球体边缘触碰相邻出口格不算进入。

连续拖动和松手吸附都检测实际经过的路径。快速长滑动即使单帧跨过整个出口格，也必须通过路径检测触发通关，不能只检查最终落点；碰撞检测先裁剪出合法移动路径，不能隔墙触发出口。

触发后立即锁定通关、提交完成记录并截停剩余移动，停止接收玩法操作，再播放小球进入出口的动画并展示结算。动画将小球收至出口中心仅用于表现，不是通关前提。通关记录只写入一次，不能重复触发结算或重复推进关卡。

“重新开始”立即将小球恢复到本关起点、地图恢复关卡指定初始状态，并清除当前提示。已用掉的本关免费提示不返还，历史通关和跳过记录不清除。该操作无广告，首版不增加二次确认。

## 三、界面与交互流程

### 3.1 页面结构

| 页面 | 主要内容 | 行为 |
| --- | --- | --- |
| 首页 | 游戏名称、继续游戏、选关、声音开关 | 无存档时“继续游戏”显示为“开始游戏” |
| 选关 | 关卡序号、解锁状态、完成状态 | 可返回已解锁关卡挑战 |
| 游玩 | 关卡标题、返回选关、状态标签、迷宫、操作按钮 | 核心操作界面 |
| 广告确认弹窗 | 本次用途、观看按钮、取消按钮 | 仅明确点击观看后请求广告 |
| 结算 | 通关文案、下一关或返回选关 | 正常推进免费 |

游玩布局从上至下为：返回与关卡信息、教学短句、居中地图、主按钮“折叠／展开”、次级操作“提示”“重新开始”。“跳过本关”使用弱化的文字按钮，与主操作及结算中的“下一关”分开。

地图按展开时的最大尺寸预留空间，两种状态都保持相同格子大小和整体居中，避免折叠时缩放导致视觉误判。折叠区采用浅色底纹加折痕标识，不能只依赖颜色区分；小球、出口、墙壁、提示箭头需在低对比环境中仍可识别。

### 3.2 主要流程

开始／继续 → 进入关卡 → 移动与切换 → 到达出口 → 结算 → 下一关。

游玩中可以重新开始、请求提示或返回选关。返回时保存最后一个已完成动作后的稳定状态；再次从“继续游戏”或选关进入未完成关卡时恢复该状态。已通关关卡再次挑战时从起点与初始地图状态开始。

### 3.3 输入优先级

弹窗或广告打开时，迷宫不响应输入；结算出现时，只响应结算界面操作。连续拖动期间持续处理当前手势，与吸附、折叠和结算互斥；吸附、折叠和结算动画期间不接收或延后执行玩法手势。用户切到后台时取消当前手势，按存档规则恢复稳定逻辑状态。

## 四、提示系统

### 4.1 提示内容

提示根据当前小球格子和地图状态计算，必须沿着一条最终能够抵达出口的有效解展示下一段操作，不使用固定的起点路线。

- 需要移动时，高亮本段道路并按顺序显示方向箭头。
- 到达应切换的位置时，高亮“折叠”或“展开”按钮，提示玩家主动点击。
- 如果当前位置下一步就应切换，只高亮按钮，不绘制多余路线。
- 在死路中，优先展示可返回有效路线的移动方向，文案为“先沿箭头返回岔路”；不自动重置。
- 本段到下一次折叠／展开操作完成为止；若先抵达出口，则在出口结束。
- 玩家走到切换位置时仍属于同一段提示。完成该切换后才清除指引；后续路线需要再次请求。
- 提示不代替玩家移动或自动切换。

### 4.2 激活与清除

提示激活期间再次点击提示按钮，仅重新强调当前路线，不扣次数、不播放广告。跟随箭头移动时清除已经走过的部分。

连续移动时，按顺序检查实际经过的道路格中心，并在吸附完成时检查最终格子；沿指引前进则逐格推进提示，不能只比较一次长滑动的最终落点。若到达的格子与提示下一步不一致，或主动进行了不同于提示要求的状态切换，清除指引，不返还已消耗次数。尚未到达新格子中心且最终吸附回当前格子、撞墙、位移不足或被拒绝的折叠不算偏离。到达提示切换位置不强制截停拖动；若继续经过该位置后的其他格子，则视为偏离。

重新开始、离开关卡、通关、跳过会清除可见指引。离开后重新进入不恢复指引，免费次数也不刷新。

### 4.3 获取与扣除

| 情形 | 处理 |
| --- | --- |
| 教学关操作引导 | 免费，可在偏离后重新给出，不消耗提示 |
| 首次进入任一关卡 | 为该关卡建立一次免费提示资格 |
| 免费资格可用，成功显示一段提示 | 标记本关免费提示已使用 |
| 本关免费提示已使用 | 弹出“看视频获得本次提示”，允许取消 |
| 广告完整完成 | 获得一次额外提示并立即显示 |
| 广告未完成、失败或取消 | 不发放提示、不改变关卡进度 |
| 已有激活提示 | 仅强调现有指引，不消耗、不进入广告 |
| 重新开始、重进关卡或重启应用 | 本关免费提示使用记录保持不变 |

“每关一次”按本地存档中的关卡 ID 记录，而不是每次开局一次。额外提示可反复通过自愿观看视频获取，每次只发放一段；不设置可购买或跨关囤积的提示背包。

教学引导只解释当前教学目标，不预先展示全关解法；如果玩家主动使用“提示”查看解题路线，仍遵守每关免费一次规则。

### 4.4 寻路口径

实现时把“原始格子坐标 + 展开／折叠状态”作为一个节点。移动到合法相邻道路、合法折叠、展开分别作为一条操作边。折叠状态下隐藏区的格子不是可用节点。

首版采用广度优先搜索，移动一格和切换一次均计一个逻辑操作，找到逻辑操作数最少的有效解；这里的操作数不是手势次数，一次长滑动可完成多个相邻格移动。同长度解按固定顺序选择，建议为上、右、下、左、切换，保证相同状态下提示稳定。最终只展示这条解中截至首次切换的片段。

若找不到解，属于关卡配置或逻辑异常：不消耗免费提示，不引导观看广告，显示“暂时无法生成提示，请重新开始本关”，并记录关卡 ID 和当前状态供排查。广告前先验证可生成路线；广告已完成但显示异常时，保留该次待发放提示，恢复本关后重试，不能要求再次观看。

## 五、通关、跳过与选关

### 5.1 正常通关

到达出口后，建议播放 0.4 秒的小球缩入出口动画，随后显示“通关成功”和“下一关”。

点击“下一关”进入顺序中的下一关：首次进入从起点和初始地图状态开始，并建立该关的一次免费提示资格。若该关已有游玩存档，则恢复其进度及提示记录，不重复赠送免费提示。

通关即保存完成记录并解锁下一关，不依赖点击“下一关”才保存。结算界面同时提供返回选关入口。重玩已通关关卡不会重复改变解锁结果。

### 5.2 卡关跳过

非教学、非最后一关且尚未通关时显示“跳过本关”。点击后弹窗显示“看视频跳过本关”，说明“完整观看后进入下一关，本关将标记为已跳过，可随时返回挑战”。按钮为“看视频跳过”和“继续挑战”。

完整观看后，记录本关已跳过、保留当前稳定进度、解锁并进入下一关。广告失败、未完成或取消，则回到原关卡原位置和状态。

跳过不播放通关动画，不增加已通关数量。之后返回该关可继续挑战或重新开始；到达出口后将展示状态更新为“已通关”。跳过历史可保留用于统计，但不与已通关标记并列显示。

### 5.3 最后一关

最后一关不提供跳过入口。到达出口后显示“当前关卡已完成”，主按钮改为“返回选关”，不生成不存在的下一关。

若仍有已跳过但未通关关卡，结算附加“还有 X 关待挑战”；仅在全部关卡真实通关时显示“全部关卡已通关”。

### 5.4 选关与状态

首次只解锁第 1 关；完成或跳过一关后解锁下一关。已解锁范围只增加，不因重玩、重开或返回教学关而倒退。

| 展示状态 | 进入规则 | 说明 |
| --- | --- | --- |
| 未解锁 | 不可进入 | 显示锁标识 |
| 未通关 | 可进入 | 包含尚未开始和进行中的已解锁关卡 |
| 已跳过 | 可进入 | 独立标识，不计入完成数量 |
| 已通关 | 可重新挑战 | 展示优先级高于跳过历史 |

## 六、首批关卡设计

关卡全部手工设计，不使用随机生成。当前发布目录只保留一关竞品参考图，后续关卡另行设计；原十二关自动生成目录与前四关固定教学约束取消。

### 6.1 当前唯一关卡：竞品参考 · 折叠接桥

- 展开尺寸：15 列 × 21 行；折叠区域：第 5～11 列（含两端，共 7 列）。折叠后左右各剩 4 列。
- 起点：底行第 2 列；出口：底行第 15 列。参考图中的黑色鼠标点不属于关卡。
- 设计意图：观察底部断路，折叠一次将左右道路接通。上方长廊保留参考布局，不要求遍历全部道路。
- 展开不能沿底路直达目标；在折叠区外折叠后可通过底路到达目标。站在中间区域不能折叠。
- 这是当前最后一关，不显示跳过；通关后显示“当前关卡已完成 / 返回选关”。
- 编辑器提供关卡列表、设计意图与卡点说明、道路/墙连续绘制、起终点设置、折叠预览、可解性检查与试玩。

### 6.1.1 道路与圆角

路宽等于格宽。道路沿格子边界铺满，边缘倒角半径为格宽的 16%，不使用圆头细线绘制道路。圆角依据完整展开地图确定，再归入左、中、右三块场景网格。

折叠只隐藏中间区域并平移左右区域；不根据新邻接关系修改圆角、不切换另一套道路网格、不在折叠过程中重建网格。两侧原有小圆角可原样相接，通行仍按道路格判断。折叠区域只以背景轻微色差表示。

### 6.2 关卡制作原则

- 建议教学图从 5 行 × 7 列起步，常规图优先控制在 7 行 × 9 列以内；折叠区宽 1～3 列。以手机上格子可辨认为先。
- 初期每关只增加一个理解点；通过折叠位置和连接关系增加难度，避免单纯扩大地图。
- 折叠区必须有清楚边界；首次进入时能辨认起点、出口和可收起部分。
- 为可回退路线留出清晰空间，不制造只能重开才可解除的陷阱。
- 不要求唯一解，但每条合法解都必须符合基础规则。
- “必须折叠／展开”的关卡要排除绕路直达的捷径。
- 不用步数排名和星级诱导玩家追求最短解；最短解只供校验及提示计算。

### 6.3 发布前校验

每张地图必须通过以下检查：尺寸与行长一致；只有一种起点和出口；二者为不同道路格且位于折叠区外；折叠列合法且左右非空；初始状态合法；起点到出口存在有效解。

校验工具还应输出最少操作数、最少必要切换次数以及一条示例解。最少必要切换次数需按“移动成本 0、切换成本 1”独立计算，不能只统计最短操作解里的切换次数。对第 3、4 关等指定教学序列，额外验证不存在绕开目标序列的解。

从起点可达的所有稳定状态应仍可到达出口；这也是提示始终可用、允许自由试错的保证。若校验失败，该关不能发布。

## 七、广告与异常处理

广告平台尚未指定，接入时以所选 SDK 的官方完成结果为准；以下为游戏内部奖励规则，不以关闭广告页面作为完成依据。

| 事件 | 游戏处理 |
| --- | --- |
| 点击广告入口 | 显示用途确认，不立即扣除或改变进度 |
| 确认观看 | 锁定玩法状态，记录用途、关卡和本次请求标识 |
| 加载中 | 显示“视频加载中”，屏蔽重复请求 |
| 加载失败或超时 | 提示“视频暂时无法播放，请稍后再试”，恢复操作 |
| 中途关闭或未满足完成条件 | 提示“视频未完整观看，未获得奖励”，保留进度 |
| 有效完成回调 | 按用途发放一次提示或跳过一次关卡 |
| 回调重复 | 按请求标识去重，不重复发放或连跳多关 |
| 回调属于旧关卡 | 不影响当前关卡，按原请求记录恢复或核对 |

等待广告期间原有提示保持冻结，失败后恢复。广告成功跳过则清除原关卡可见提示；提示广告成功后在冻结时的位置计算并展示路线。

奖励提交与请求处理标记应一起持久化。切后台或意外退出后，有已确认完成且尚未兑现的记录才补发；无法确认完成的请求不自行发奖。应在 SDK 联调时验证退出、恢复与回调时序。

无网络时可正常玩已内置关卡和使用未消耗的免费提示；广告入口失败不能阻挡免费玩法。建议广告加载超时初值为 10 秒，实际按 SDK 能力调整。

## 八、存档与恢复

首版建议保存下列数据，不保存动画进度或屏幕坐标：

| 数据 | 目的 |
| --- | --- |
| 存档结构版本、关卡内容版本 | 支持后续兼容和地图修订 |
| 当前关卡、最高解锁关卡 | 支持继续游戏和选关 |
| 各关是否通关、是否有跳过历史 | 区分真实完成与跳过 |
| 各关免费提示是否已用 | 防止重开或重启刷新 |
| 各未完成关卡原始格子坐标、折叠状态 | 恢复稳定进度 |
| 教学完成标记、声音与震动设置 | 保留基础偏好 |
| 待处理广告请求、已确认奖励及去重标识 | 防止漏发和重复发放 |

移动吸附完成、状态切换、提示消费、奖励发放、通关和跳过后更新存档；返回选关和切后台时补充保存。连续拖动过程中不持久化格间坐标。存档以原子写入或等效方式防止半写入。

移动过程中持续验证路径合法性，松手吸附完成后提交稳定格子与存档。拖动或吸附期间返回选关、切后台或意外退出时，取消本次未完成移动，恢复到本次手势开始前的稳定格子；已清除的提示不返还次数。折叠动画未完成时恢复到切换前的稳定状态。若途中已触发出口，则立即提交出口位置及通关结果，后续通关表现被打断也不撤销完成记录。

地图版本变更导致旧坐标非法时，将该关位置恢复到起点和初始状态，保留通关、解锁及免费提示使用记录。损坏存档优先读取有效备份；无可恢复数据时提示进度恢复失败并创建初始存档。

## 九、关卡配置与模块职责

### 9.1 关卡配置字段

| 字段 | 含义 | 限制 |
| --- | --- | --- |
| levelId / order | 稳定关卡标识、展示顺序 | ID 唯一，不以数组下标代替永久 ID |
| title / contentVersion | 标题、内容版本 | 地图变动时更新版本 |
| rows / columns / cells | 行列数、道路与墙数据 | 数据尺寸一致 |
| start / exit | 原始格子行列坐标 | 道路、不同格、折叠区外 |
| foldStartColumn / foldWidth | 隐藏区域起始列与列数 | 连续完整列，左右均有保留区域 |
| initialState | 初始展开或折叠 | 两种枚举值 |
| isTutorial / tutorialSteps | 教学标记与条件式步骤 | 教学不能依赖固定操作时长 |
| designGoal | 关卡目标及校验要求 | 仅用于制作与验收 |

最后一关由发布关卡列表的顺序推导。跳过资格由“非教学、非最后、未通关”统一判断，避免多个配置字段相互矛盾。

### 9.2 实现职责建议

- 地图规则：处理原始坐标、邻接关系、墙体判定和切换合法性。
- 表现层：负责格子布局、小球移动、纸张折叠、接缝与提示动画，不自行修改格子归属。
- 关卡流程：处理教学、游玩、结算、解锁和最后一关判断。
- 提示服务：与地图规则共用邻接逻辑，计算解并管理当前提示片段。
- 广告服务：封装展示结果、请求去重和奖励兑现，不直接以界面跳转代替奖励判定。
- 存档服务：保存稳定状态及一次性结果，处理版本兼容和损坏恢复。

该职责划分可用于当前 Unity 工程，具体脚本与框架接入方式由开发阶段确定。

## 十、美术、动效与音效

整体采用简洁纸张迷宫风格，以道路可读性为第一优先级。墙壁有实体感，道路保持连续；折叠区通过浅底纹、双边折痕明确范围。折叠后保留细接缝，不让玩家误以为两侧仍隔着墙。

小球与出口使用不同形状或图案辅助识别；提示路线采用半透明高亮与箭头，不覆盖墙壁和出口。高亮按钮可缓慢呼吸，避免频闪。

基础音效包括移动、撞墙、折纸、按钮、提示和通关。声音可关闭；震动作为可选反馈，不作为唯一信息渠道。画面需适配安全区，底部按钮避免贴近系统手势区域。

首版素材清单：小球、道路、墙壁、起点、出口、折叠区底纹、折痕、接缝亮线、四向提示箭头、按钮状态、选关状态图标、结算面板及上述基础音效。

## 十三、制作顺序与试玩观察

1. 玩法原型：完成网格移动、固定区域折叠、格子归属和出口判定，用少量测试地图验证连接关系。
2. 关卡工具：接入配置、状态图寻路和关卡校验，验证当前手工竞品参考关。
3. 完整单机流程：完成提示、重开、选关、解锁、结算和本地存档。
4. 内容与表现：先完成这一关的美术、动效和屏幕适配；后续关卡逐关手工设计。
5. 广告接入：使用测试环境验证成功、取消、超时、重复回调和恢复，再进行真实平台验收。

试玩重点观察：玩家能否理解折叠区边界、是否知道接缝需要两侧都有道路、能否理解展开后仍留在原格、是否将“下一关”误认为必须看广告，以及提示是否过早泄露整关解法。

建议记录关卡进入、首次折叠、非法折叠、提示使用、重开、通关、跳过及广告结果等事件，以关卡和内容版本汇总完成率、提示使用率、跳过率和解题时长。时长与操作数仅用于调优，不在玩法中设置限制；实际采集方式在发行平台确定后落实。

发行平台、广告 SDK、最终关卡数量及地图资源仍需在开发阶段确定；不影响本策划中的移动、折叠、提示与通关规则实施。
